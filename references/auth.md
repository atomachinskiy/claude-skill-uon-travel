# Авторизация в U-On.Travel API

## Получение API-ключа

API-ключ выпускается владельцем кабинета через UI:

1. Зайти в кабинет (URL вида `id<NNNNN>.u-on.ru`).
2. **Настройки → Интеграции → API**.
3. Нажать «**+ добавить новый API-ключ**».
4. Заполнить «Наименование» (произвольно, для собственного учёта).
5. **Обязательно** отметить чекбоксы **POST?** и **GET?** — без них API не работает.
6. Опционально — заполнить IP-whitelist (через запятую). Без whitelist ключ работает с любого IP.
7. Нажать «Сохранить».
8. **Скопировать ключ сразу** — он показывается единожды, после сохранения только маска `0X7rqw*******`.

Если ключ потерян — создаём новый, старый можно удалить.

## Структура запроса

Ключ передаётся **в URL** (не в header):

```
https://api.u-on.ru/{KEY}/{endpoint}.{json|xml}
```

Никакого `Authorization: Bearer` или OAuth.

Это упрощает интеграцию, но накладывает требования к хранению:

- Не коммитить ключ в git
- Хранить в переменной окружения, `.env`, или `~/.claude/secrets/uon-api-key`
- Логи с URL фильтровать (ключ в логах — компрометация)

## IP whitelist

В production рекомендую включить whitelist на конкретные IP. Множественные адреса перечисляются через запятую:

```
52.29.159.27, 1.2.3.4
```

Запросы с других IP получат отказ на уровне TLS-handshake (не HTTP 403, а обрыв соединения).

## Что включают POST? и GET?

Это два независимых флага в UI:

- **GET?** — разрешены запросы чтения (GET-методы)
- **POST?** — разрешены запросы записи (POST-методы)

Можно выпустить два разных ключа — один read-only, второй write — и хранить их в разных контекстах (например, ключ для BI-дашборда только GET).

## Лимиты

| Параметр | Значение |
|----------|----------|
| Rate limit | 10 запросов / секунду |
| HTTP only | HTTPS обязателен (HTTP не работает) |
| Timeout | стандартный, ответ обычно < 1 сек |

Скилл соблюдает rate limit через искусственную задержку 150ms между вызовами (`UON_THROTTLE_MS`).

## Что НЕ поддерживается

- **OAuth** — нет, только static ключ
- **Refresh tokens** — нет, ключ постоянный
- **Sandbox** — нет, тестируем на боевом или триальном кабинете
- **Версионирование** — нет, API один, изменения ловим по реальным ответам
- **Ролевая модель** — нет, ключ имеет полный доступ ко всему кабинету

## Совет по безопасности для агентств

Если работаешь с кабинетами нескольких клиентов:

- Заводить отдельный ключ для каждого кабинета клиента
- Хранить в зашифрованном виде (Vault, 1Password, AWS Secrets Manager)
- При расторжении договора — попросить клиента удалить ключ из U-On UI
- В скилле использовать `UON_API_KEY` через окружение, не хардкодить
